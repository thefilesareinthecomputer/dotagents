## Agent frameworks & SDKs

- [langchain-ai/langchain](https://github.com/langchain-ai/langchain) - broad LLM/agent framework; largest integration ecosystem. Docs: [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview) (full page set in ledger).
- [langchain-ai/deepagents](https://github.com/langchain-ai/deepagents) - LangChain's deep/long-horizon agent pattern. See the harness entry below for the current version and caveats.
- [run-llama/llama_index](https://github.com/run-llama/llama_index) - data + agent framework over indices, graphs, retrievers.
- [openai/openai-agents-python](https://github.com/openai/openai-agents-python) - lightweight multi-agent SDK (tools, sessions, handoffs, tracing).
- [google/adk-python](https://github.com/google/adk-python) - Google Agent Development Kit. Docs: [adk.dev](https://adk.dev/2.0/).
- [google/adk-samples](https://github.com/google/adk-samples) - official ADK recipe corpus: runnable agents covering OAuth flows, session memory, guardrails and RAG across Python/TS/Go/Java/Kotlin, split into maintainer-owned `core/` and community `contrib/` with a published Recipe Checklist and Handbook gating contributions. Apache-2.0 (~10.2k★, checked 2026-08-14). The two-tier corpus plus mechanical acceptance checklist is a governance shape directly copyable to a skills library; the recipes are labeled demonstrations, not production code.
- [google/agents-cli](https://github.com/google/agents-cli) - Google agents CLI. Docs: [google.github.io/agents-cli](https://google.github.io/agents-cli/).
- [microsoft/agent-framework](https://github.com/microsoft/agent-framework) - MS successor framework (Python/.NET). Docs: [learn.microsoft.com/agent-framework](https://learn.microsoft.com/en-us/agent-framework/).
- [strands-agents/sdk-python](https://github.com/strands-agents/sdk-python) - model-driven SDK with built-in MCP. Docs: [strandsagents.com](https://strandsagents.com/).
- [stanfordnlp/dspy](https://github.com/stanfordnlp/dspy) - programming-not-prompting; compiled LM pipelines.
- [karpathy/llm-council](https://github.com/karpathy/llm-council) - local web app running one query through several models via OpenRouter in three stages: independent first opinions, **anonymized peer review** where each model ranks the others' answers relabeled A/B/C, then a designated chairman model synthesizing the final answer. Models are hardcoded in `backend/config.py`; needs an OpenRouter key. 24,540★, last push **2025-11-22** (GitHub API, checked 2026-09-02) - the author states it is "99% vibe coded", a weekend hack, and explicitly unsupported, and the commit history agrees. The mechanism worth knowing is the anonymization, not the code: the reported finding is that a model will rank a rival's answer above its own once it cannot tell whose is whose. Caution: **the repo carries no license file**, so it is all-rights-reserved despite the star count - read it for the mechanism and reimplement, never copy source.
- [Agno docs](https://docs.agno.com/introduction) - agents/teams/workflows/AgentOS runtime (full reference set in ledger).
- [NVIDIA/NeMo-Agent-Toolkit](https://github.com/NVIDIA/NeMo-Agent-Toolkit) - framework-agnostic interop, eval and profiling layer that wraps agents/tools from an existing framework as composable functions; YAML workflows, MCP client *and* server, and a profiler reporting tokens, latency, throughput, bottlenecks and concurrency spikes. Apache-2.0, `pip install nvidia-nat`, v1.8 (2026-06-16), ~2.5k★ (checked 2026-07-28). Plugins for LangChain/LangGraph, LlamaIndex, CrewAI, Semantic Kernel, Google ADK, AutoGen and Agno, plus LiteLLM/Bedrock/OCI/OTel; no GPU or NVIDIA licence required. Not a replacement framework - it runs alongside one. ⚠️ Renamed twice (`agentiq`→`aiqtoolkit`→`nvidia-nat`, CLI `aiq`→`nat`) with every compatibility shim now deleted, and breaking changes ship in *minor* releases - pin it and distrust pre-2026 tutorials. Docs: [docs.nvidia.com/nemo/agent-toolkit](https://docs.nvidia.com/nemo/agent-toolkit/latest/index.html), [PyPI](https://pypi.org/project/nvidia-nat/).
- [NVIDIA-AI-Blueprints/aiq](https://github.com/NVIDIA-AI-Blueprints/aiq) - AI-Q research agent, the flagship reference build **on** the NeMo Agent Toolkit (pinned 1.8.0) plus LangChain Deep Agents. Apache-2.0 source; defaults to hosted Nemotron NIMs, so no local GPU is needed to run it (checked 2026-07-28). Documented as composable with the RAG blueprint, and forked by `biomedical-aiq-research-agent` - the clearest worked example of blueprints-as-building-blocks.

MIT, TypeScript (~12.4k★, checked 2026-08-08). **Not a local CLI**: the `qm` command only scaffolds a deployment repo (`qm init . --org <slug> --target <fly-or-aws>`); you run it in your own Fly or AWS account with your own model keys, and there is no hosted tier. Skills come from `deploy/layers/<org>/` and git-imported skill packs rather than any `~/.agents/skills` convention, so a shared skills tree reaches it as a pack, not a path. Caution: YC frames it as early and buggy, and it is infrastructure you operate rather than a binary you install.

- [andrewyng/openworker](https://github.com/andrewyng/openworker) - desktop agent that works across local files and 25+ connected apps (Slack, GitHub, Jira, Notion, Gmail), decomposing a task into steps and gating consequential actions behind approval. MIT, Python + React/TS with a Rust STT sidecar (~7.1k★, checked 2026-07-27). Open beta, 4 contributors, first published 2026-07-20 - worth reading as a reference implementation of human-in-the-loop approval gating on a desktop agent. Re-verified 2026-08-14: still beta, MIT, ~14.5k★, no material change.
- [ogulcancelik/herdr](https://github.com/ogulcancelik/herdr) - terminal multiplexer for concurrent agents: one Rust binary showing every agent's state (blocked / working / done), sessions surviving detach and restart, and a socket API agents call to spawn their own panes. Apache-2.0 (~21.1k★, checked 2026-07-27). The tmux-shaped answer to running several harnesses at once; a plugin marketplace is bolted on, so vet extensions separately.
- [shepherd-agents/shepherd](https://github.com/shepherd-agents/shepherd) - runtime substrate that makes an agent run a reversible, git-like trace: fork, replay, and revert any execution, with syscall-level permission enforcement (macOS Seatbelt, Linux Landlock) and outputs held as reviewable proposals. MIT, Python 3.11+ (~1.6k★, checked 2026-07-27). ⚠️ Self-declared alpha, APIs changing; macOS/Linux only. The fork-and-replay idea is the reusable part. Re-verified 2026-08-14: still early alpha; companion repo [shepherd-experiments](https://github.com/shepherd-agents/shepherd-experiments) (MIT) now carries the paper's meta-agent applications, microbenchmarks and a frozen substrate snapshot - a commit covers the agent process and filesystem together, which is what makes a rewind restore live state, not just files.
- [EverMind-AI/Raven](https://github.com/EverMind-AI/Raven) - self-improving agent harness over [EverOS](https://github.com/EverMind-AI/EverOS) (its markdown-native local memory layer): durable user + agent memory, evolving skills, Agent Templates, a scheduler for proactive runs, and tracing. Apache-2.0, Python (~2.8k★, checked 2026-07-27). Backed by EverMind (Shanda Group). ⚠️ Pre-1.0 and pre-alpha by its own README; not on PyPI (install is a GitHub Release wheel); its memory benchmark claims are first-party.
- [taracodlabs/aiden](https://github.com/taracodlabs/aiden) - autonomous "work engine" driving files, terminal, browser and APIs from a prompt, bundling 76 skills and 121 tools across 19 providers. TypeScript/Node (~0.8k★, checked 2026-07-27). ⚠️ **AGPL-3.0 core** with paid commercial relicensing for closed-source use - a dual-license trap, not a permissive dependency. Solo-maintained (2 contributors).
- [patoles/agent-flow](https://github.com/patoles/agent-flow) - live visualization of a Claude Code or Codex run: an interactive node graph of the agent branching into subagents and tool calls, with a timeline and JSONL log replay. Apache-2.0, TS (~1.4k★, checked 2026-07-27). Debugging and post-mortem tooling for orchestration, adjacent to the eval stack below.
- [cobusgreyling/loop-engineering](https://github.com/cobusgreyling/loop-engineering) - patterns, starters and CLI tools (`loop`, `loop-audit`, `loop-init`, `loop-cost`) for the discipline of *designing the loop an agent runs in* rather than the prompt - scheduled triage, CI sweeps, cost accounting - across Claude Code, Codex, Grok and others. MIT (~9.5k★, checked 2026-07-27). Half working code, half essays; the essays are the reason to read it.
- [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) - DeepSeek's open-source Claude Code rival: a pnpm monorepo where every capability is a Cordis plugin joined at "Capability Seams" - a Service Definition declares an interface (`ctx.llm`, `ctx.fs`), providers implement it, tools consume it - so models, tools, skills, sandboxes, storage and even the agent loop swap independently. Four runtime modes: Standard (full coding agent with skills, subagents, planning), Code mode (the model writes orchestration code issuing many tool calls instead of one per turn), Minimal (bare shell + editor, a ready-made control condition for benchmarking a model without harness scaffolding), Creator (inspect and recompose the runtime). MIT (~94.7k★, checked 2026-08-14). Caution: v0.1 developer preview, compatibility-breaking changes expected. Readable prior art for skills/subagent/session design in a peer harness.
- [Untrivial-ai/agent-orchestrator](https://github.com/Untrivial-ai/agent-orchestrator) - meta-harness supervising *other people's* CLI coding agents: a Go daemon (`ao` CLI, loopback HTTP, SQLite, lifecycle/reaper, one adapter per harness across ~25 of them) plus an Electron/React Kanban supervisor over a generated OpenAPI client. The unit of work is a **worker** - one task, one agent process, one git worktree and branch - and the owning session owns everything that happens to that branch's PR. Verification is outsourced entirely to CI and PR review; there is no LLM critic. Failure handling is a declarative reaction engine in `agent-orchestrator.yaml` mapping events (`ci-failed`, `changes-requested`, `agent-stuck`) to actions with `retries` and `escalateAfter` as either a count or a duration. The stated architectural rule is **Observe -> Update -> Derive**: poll SCM/CI, reduce observed facts into SQLite, compute status at read time, never store a derived status. All state under `~/.ao`. Apache-2.0, Go + TypeScript (~10.9k★, checked 2026-09-02); moved from `ComposioHQ/agent-orchestrator` and the npm `@aoagents/ao` is frozen at 0.10.0 and legacy. Caution: **no token or cost budget anywhere**, despite automatic retry across premium agents - the most serious gap in it. Handoff is plain text injected into the agent's terminal with no schema and no delivery guarantee. Issue #4122 shows two epoch counters mutated by different subsystems that must agree, already producing session-resume bugs. Pre-rewrite TypeScript tutorials still rank in search and describe a system that no longer exists. No novel orchestration idea here; the value is execution quality and harness coverage.
- [danielmiessler/LifeOS](https://github.com/danielmiessler/LifeOS) - renamed from `Personal_AI_Infrastructure` (PAI): personal-AI harness layer over Claude Code (TypeScript + Bash, requires bun) supplying hooks, skills, the TELOS personal-context format, agentic routing and persistent memory, distributed as one self-contained installable skill whose payload rides under `install/`, versioned at the release tag because harnesses ignore version fields in skill frontmatter. Installs by handing the agent a URL; the agent detects the harness and wires hooks with permission. MIT (~18.5k★, checked 2026-08-14). Caution: one person's heavily-branded personal system - the packaging, install-by-agent and release-tag-versioning patterns are the value, not the content.

- [chroma-core/chroma](https://github.com/chroma-core/chroma) - embeddings/vector DB.

- [Evokoa/pgGraph](https://github.com/Evokoa/pgGraph) - Rust Postgres extension adding graph traversal over tables you already have: compiles selected relational tables into a derived CSR adjacency index and exposes shortest-path, traversal and relationship queries as SQL functions in a `graph` schema - no second database, no new query language (contrast Apache AGE), and your tables stay the source of truth so constraints, RLS and backups remain ordinary Postgres concerns. Apache-2.0, 1.0.0 supporting PG 14-18 (~1k★, checked 2026-08-14). Caution: index rebuilds are expensive on large tables and refresh is user-managed. The derived-rebuildable-index pattern transfers to any KG or memory layer already living in Postgres.

## RAG / retrieval / knowledge engines

- [infiniflow/ragflow](https://github.com/infiniflow/ragflow) - deep-document RAG engine with agent features.
- [neuml/txtai](https://github.com/neuml/txtai) - embeddings DB + semantic search + LLM workflows.
- [VectifyAI/OpenKB](https://github.com/VectifyAI/OpenKB) - compiles heterogeneous documents (PDF, Word, Markdown) into a **persistent interlinked Markdown wiki** rather than retrieving at query time. Nodes are wiki pages typed as summary, concept or entity (person/org/place/product); edges are cross-document links the build pass maintains automatically; storage is plain Markdown in a `wiki/` folder, Obsidian-compatible. Retrieval is **vectorless** - hierarchical tree indexing via PageIndex, no embeddings and no vector DB. Apache-2.0, Python, 4,410★, last push **2026-07-22** (GitHub API, checked 2026-09-02) - six weeks quiet, so treat "actively maintained" as unproven. The two ideas worth taking: the hard split between *compile once into a durable artifact* and *retrieve at query time*, and a working non-embedding retrieval strategy over long documents. Caution: building the KB requires an LLM API (OpenAI Agents SDK + LiteLLM), so it is not offline; its "Open Knowledge Format" is Vectify's own spec and is worth confirming before citing it as a standard.
- [stanford-oval/storm](https://github.com/stanford-oval/storm) - research/report synthesis from web sources.
- [LearningCircuit/local-deep-research](https://github.com/LearningCircuit/local-deep-research) - local deep-research pipeline.
- [Canner/WrenAI](https://github.com/Canner/WrenAI) - governed text-to-SQL for agents: a semantic layer (Modeling Definition Language capturing models, relationships, metrics and access policy) sits between the question and 20+ warehouses, so retrieval is schema-aware and answers are traceable to approved definitions rather than guessed joins. Python (~16.7k★, checked 2026-07-27). The pattern to steal when an agent must query a real warehouse: **model the semantics first, generate SQL second.** ⚠️ Multi-licensed by path - `core/`, `sdk/`, `skills/`, `examples/` are Apache-2.0, `docs/` is CC-BY-4.0, and the LICENSE pre-stages **AGPL-3.0** for future modules that do not exist yet (verified 2026-07-27). Re-read the path→license table before depending on any new subtree.

## Privacy, security & red-team

- [microsoft/agent-governance-toolkit](https://github.com/microsoft/agent-governance-toolkit) - runtime policy enforcement for autonomous agents, and the sharpest statement of the **intercept-in-code, not in-prompt** principle: every tool call, message send and delegation is intercepted in deterministic application code before model intent reaches the wire, so a denied action is structurally impossible rather than discouraged. Policy is evaluated from YAML, OPA/Rego or Cedar rather than baked in. MIT, Python 3.10+ core with TypeScript, .NET, Rust and Go SDKs, 6,180★, pushed 2026-09-02 (GitHub API, checked 2026-09-02); deployable as an AKS sidecar; governed by a TSC actively recruiting multi-org maintainers; v3.6.0 splits the architecture across six specs - identity/trust, coordination, execution control, SRE governance, MCP security gateway, audit/compliance. The most directly relevant published reference architecture for governing agents that run shell commands and touch files. Cautions: Microsoft-signed **public preview**, not GA. Its "992 conformance tests" and its coverage claim against the OWASP agentic list are both self-reported. It cites that list under a name OWASP does not use (see the note under Section K), which is a small tell about how closely the mapping was made. And the structural limit of in-process hook interception is that it governs only the code paths that call the hook - a process-separated gateway does not have that hole. Reclassified from `learning` on 2026-09-02; it is a security control plane, not a reading list.
- [opensandbox-group/OpenSandbox](https://github.com/opensandbox-group/OpenSandbox) - general-purpose sandbox runtime for agent workloads, with the architecturally interesting move being a **lifecycle/execution split**: a Python/FastAPI control-plane server creates and tears down sandboxes while a separate Go execution daemon (`components/execd/`) handles command and filesystem operations inside one, with session-ID reattachment for stateless workers. Docker locally, Kubernetes distributed; Command, Filesystem and Code Interpreter primitives; an `osb` CLI and an MCP server. Worked examples run Claude Code, Gemini CLI, Codex CLI, OpenCode, Qwen Code and Kimi CLI inside the sandbox, plus Chromium/Playwright and desktop-VNC variants. Apache-2.0, Go, 14,919★, pushed 2026-09-02 (GitHub API, checked 2026-09-02); releases keylessly signed with Cosign carrying provenance attestations, and changes go through a PEP-style OSEP proposal process. Structurally serious, not a toy. Caution: the organizational backing behind "opensandbox-group" was not established - verify governance before any production dependency.
- [openai/privacy-filter](https://github.com/openai/privacy-filter) - PII detection/masking. [Announcement](https://openai.com/index/introducing-openai-privacy-filter/) · [forum](https://community.openai.com/t/openai-privacy-filter-for-detecting-and-masking-pii-in-text/1379537).
- [zeroc00I/LLM-anonymization](https://github.com/zeroc00I/LLM-anonymization) - LLM anonymization.
- [usestrix/strix](https://github.com/usestrix/strix) - autonomous security/pentest agents.
- [google/magika](https://github.com/google/magika) - ML file-type detection.
- [NVIDIA/NeMo-Guardrails](https://github.com/NVIDIA/NeMo-Guardrails) - programmable input/output rails for LLM-based conversational systems: topic boundaries, safety checks and dialogue policy declared as config rather than prompt text. Apache-2.0, v0.23.0, ~6.8k★ (checked 2026-07-28; release date not captured).
